Flujo del Chat Admin

Como viaja un mensaje desde que el admin escribe hasta que ve la respuesta en pantalla.

Vista general

El chat es streaming SSE en tiempo real. El admin escribe, el servidor decide de donde sacar la informacion, llama al LLM y va emitiendo tokens. Al terminar, opcionalmente reformatea la respuesta en bloques visuales (Generative UI).

1
Frontend envia el mensaje
POST /api/v1/chat/admin con el texto. Abre una conexion SSE para recibir la respuesta en streaming.
2
Small talk check
Si es un saludo, despedida o "quien eres", responde con un mensaje prefabricado (0 tokens, 0 latencia). Si no, continua.
3
Recuperacion (RAG ladder)
Busca en 3 escalones: chunks por similitud → documentos completos → conocimiento general. El primero que tenga resultados gana.
4
Org snapshot
Lee de la BD el estado actual: empleados, cursos, progreso, competencias, documentos. Se inyecta en el prompt como contexto.
5
Construccion del prompt
System prompt (persona + reglas) + historial (8 turnos) + turno actual (snapshot + docs + pregunta).
6
Streaming de tokens
El LLM responde token a token. Cada token se emite como evento SSE token y aparece en pantalla al instante.
7
Layout (opcional)
Si la respuesta tiene 220+ caracteres y Generative UI esta activo, una segunda llamada al LLM clasifica la forma (tabla, pasos, callout, definicion) y se renderiza como bloque visual.

Escalera de RAG

El sistema nunca falla: siempre responde. La pregunta es de donde saca la informacion.

1
Chunks por similitud chunks
Embedding de la pregunta → busqueda semantica en document_chunks → top 5 con score ≥ 0.25. Si hay resultados, se formatean con [Fuente N] y se pasan al LLM.
2
Documentos completos document
Si no hay chunks, busca documentos de la org con full_text. Ranking lexico (coincidencia de palabras). Max 3 docs, 4000 chars cada uno.
3
Conocimiento general general
Sin documentos. El LLM responde con conocimiento propio. El frontend muestra "Conocimiento general: no sale de la documentacion subida".

System prompt

El prompt se compone de 3 bloques que se concatenan segun el contexto:

Bloque 1 — Persona
Eres el asistente del administrador de SkillNet. Hablas con la persona que gestiona los cursos, los documentos y los empleados.

Como respondes: en el idioma de la pregunta, conciso y operativo. Si hay mas de dos pasos, los enumeras.

Lo que no haces nunca: no te inventas cifras. No dices "no tengo informacion" y te callas — ofreces lo que si puedes. No copias los datos tal cual, son tu material de consulta.
Bloque 2 — Datos de la plataforma (si hay snapshot)
Tienes un bloque "DATOS DE LA PLATAFORMA" con el estado real de esta organizacion, leido de la base de datos ahora mismo.

Decide de que va la pregunta:
(A) Gestion → usa los datos, nombres y numeros concretos.
(B) Contenido → usa los documentos o criterio general.
(C) Sobre ti → ni datos ni documentos.

Limites: toda cifra tiene que estar literalmente en el bloque. No sumes, no promedies, no estimes. No hables de personas que no aparezcan.
Bloque 3 — Grounding (segun escalon RAG)
chunks "Tienes fragmentos recuperados de la documentacion. Apoyate en ellos y cita con [Fuente N]."

document "Tienes el texto COMPLETO de documentos. Cita con [Fuente N]."

general "No hay documentacion que responda a esto. Responde con conocimiento general y dilo en la primera linea. No escribas [Fuente N]."

Org snapshot

Se lee de la BD en cada pregunta y se inyecta como texto tabulado en el turno del usuario (antes de la pregunta, para que el LLM lo tenga de contexto).

DatoLimiteIncluye
EmpleadosMax 40Nombre, rol, cursos asignados, progreso, competencias (max 8), nodos dominados
CursosTodosTitulo, estado, modo delivery, unidades, asignaciones
DocumentosMax 25Solo titulos, no contenido
Datos de privacidad excluidos

Nunca se incluyen: accessibility, experience_level, format_vector, goal, learning_profile, preset, tutor_notes. El perfil de aprendizaje es privado entre el empleado y el sistema.

Protocolo SSE

La respuesta llega como una secuencia de eventos Server-Sent Events. El frontend los procesa en orden:

1
grounding
Tipo de fuente: "chunks", "document" o "general". El frontend sabe la procedencia antes del primer token.
2
org_data
Resumen numerico: empleados, cursos, documentos. Solo admin.
3
token
Un fragmento de texto de la respuesta. Se repite N veces mientras el LLM genera.
4
citations
Lista de fuentes citadas: [{document, section, page}].
5
done
Respuesta completa. El input se habilita aqui — el usuario ya puede escribir.
6
layout_start
Empieza el reformateo visual (segunda llamada LLM). Opcional.
7
ui
Programa OpenUI Lang validado. El frontend reemplaza la prose por bloques visuales.

Layout (Generative UI)

Despues de done, si la respuesta tiene 220+ caracteres, una segunda llamada al LLM clasifica la forma de la respuesta y la reformatea en bloques. El servidor escribe el programa OpenUI Lang, no el modelo.

FormaCuandoEjemplo
stepsProcedimiento con pasos en orden"Para abrir el turno: 1. Revisar reservas, 2. Contar fondo..."
tableComparacion de 2+ cosasTabla de empleados con progreso
calloutRegla critica, limite o excepcion"La frase 'creo que no lleva' esta prohibida"
definitionConceptos con explicacionLos 14 alergenos con descripcion
proseNada de lo anteriorSe queda como texto plano

Validaciones antes de servir el layout:

  • invented_figures — rechaza si aparecen numeros que no estaban en la respuesta original
  • validate_chat_program — parsea, rechaza QuizItems, re-serializa desde UISpec
  • Si falla → se sirve la prose original (nunca falla para el usuario)

Small talk

Saludos, despedidas y preguntas de identidad se responden con mensajes prefabricados. Coste cero de tokens, latencia minima.

CategoriaEjemplosRespuesta
Saludo"hola", "buenas", "que tal"Presentacion + capacidades
Agradecimiento"gracias""A mandar. Si necesitas otra cosa..."
Despedida"adios", "hasta luego""Hasta luego. Aqui me tienes..."
Identidad"quien eres", "que puedes hacer"Descripcion + capacidades

El matcher es restrictivo: max 6 palabras y coincidencia completa. "Hola, como van mis empleados" no es small talk — es una pregunta real.
