Como funciona

  • Click en un nodo lo expande y muestra el editor inline (como un accordion)
  • Drag handle a la izquierda para reordenar arrastrando
  • Lineas SVG conectan nodos con sus prerequisitos visualmente
  • Chips numerados en cada nodo muestran de que depende
  • Solo un nodo expandido a la vez

Pros

  • Orden natural arriba-abajo
  • Prerequisites siempre visibles
  • Funciona bien en movil
  • Reutiliza @dnd-kit existente

Contras

  • Se enreda con muchas dependencias cruzadas
  • Scroll largo con 15+ nodos
  • No muestra rutas paralelas

Como funciona

  • Columnas automaticas por profundidad del DAG (sin prereqs = izquierda, final = derecha)
  • Flechas horizontales entre columnas muestran dependencias
  • Click en nodo abre panel lateral (drawer) con editor
  • Nodos paralelos (sin dependencia entre si) quedan en la misma columna
  • El admin ve la "linea de produccion" del curso de un vistazo

Pros

  • Muestra paralelismo (nodos independientes)
  • Imposible crear orden invalido
  • Visualmente potente
  • Buen uso del espacio horizontal

Contras

  • Scroll horizontal en cadenas profundas
  • Mal en movil
  • Admin no controla la posicion
  • Requiere mas implementacion (SVG routing)

Como funciona

  • Mini-mapa SVG arriba muestra el DAG completo como circulos + flechas (solo lectura, actualizado en tiempo real)
  • Chips numerados en cada fila: prerequisitos de un vistazo sin expandir
  • Click en fila la expande con editor inline (accordion)
  • Prerequisites editables como tags removibles + boton "+ Anadir"
  • Drag para reordenar (igual que ahora con @dnd-kit)

Pros

  • Menor salto cognitivo (es una lista mejorada)
  • Funciona perfecto en movil
  • Mini-mapa da contexto sin forzar interaccion
  • Facil de implementar, reutiliza lo existente
  • Base para evolucionar a A si se necesita

Contras

  • Menos visual que A o B
  • Mini-mapa solo lectura
  • Con muchos prereqs, los chips se acumulan

Como funciona

  • Grid por fases: filas = profundidad de prerequisitos (automatico, no manual)
  • Cards de receta con borde de color segun criticality
  • Click en card abre modal FLIP (la card crece hasta ser el modal) para editar
  • Flechas entre fases muestran el flujo general
  • Cards paralelas en la misma fila = se pueden estudiar en cualquier orden

Pros

  • Metafora de "receta" relevante para el target
  • Modal FLIP ya existe en el codebase
  • Buen uso del espacio (grid compacto)
  • Muestra paralelismo y fases

Contras

  • Complejo de implementar (grid + FLIP + routing SVG)
  • En movil colapsa a una columna, pierde el concepto de fases
  • Modo "conectar" prerequisitos es un patron nuevo
  • Drag entre fases es complejo

Comparativa

Todos los conceptos lado a lado para decidir.

Reutiliza codigo existente Media Baja Alta Media

Maneja 15 nodos Media (scroll) Alta Alta Alta
Factor "wow" Medio-Alto Muy Alto Medio Alto

Estrategia recomendada

C (Outline) como base inmediata: es el menor salto desde lo actual, funciona en todos los tamanos, y el mini-mapa da contexto visual. Despues, si el feedback pide mas visualizacion de dependencias, evolucionar a A (Vertical Flow) anadiendo las lineas SVG — la estructura de C es compatible.

D (Recipe Grid) es la alternativa si quieres maximizar el "wow" y la metafora de fases, pero cuesta mas implementar y el responsive es peor.

B (Canvas Lanes) es el mas visualmente potente pero el peor en movil y el que mas se aleja del patron de lista que el admin ya conoce.
