Desfasado en un punto (2026-08-28). Las maquetas de abajo muestran un badge de minutos por nodo y un total en la barra lateral que ya no existen. El campo estimated_minutes se retiro de los prompts, de los contratos de API y de toda la interfaz: lo generaba un modelo que aun no habia visto la leccion, no se contrastaba con nada, y sumado producia estimaciones de horas en cursos de veinte minutos. Grupos de render

El componente tiene tres grupos de render segun la fase. Esto es importante para entender que animaciones aplican donde.

Grupo Fases Como se renderiza Animacion
Morph flow choose details schema Un solo bloque de JSX al final del componente, dentro de <LayoutGroup> layoutId para morph forward
AnimatePresence mode="wait" para swaps internos
useInstantLayoutTransition para backward

!
Los early returns rompen el morph. Cuando pasas de schema a assign, el early return hace que el <LayoutGroup> se desmonte. El layoutId desaparece, no hay morph inverso. Esto es intencionado: la fase assign es un contexto nuevo.

Como funciona el click

Admin hace click en una card → setSource('cero') o setSource('documentos')
Click es toggle: si ya estaba seleccionada, setSource(null)
La card seleccionada tiene border-primary + bg-primary-subtle
Aparece boton "Continuar" (AnimatePresence fade). Click → confirmSource() → setPhase('details')

layoutId: la clave del morph

Cada card tiene un layoutId unico: "source-card-documentos" y "source-card-cero". Cuando expanded pasa a true, solo se renderiza la card seleccionada (la otra desaparece del DOM). Framer Motion ve que el mismo layoutId ahora tiene un tamano/posicion diferente y anima automaticamente el cambio (tecnica FLIP).

// Renderizado condicional — solo la card activa se queda {activeCard === 'documentos' || !expanded} && ( <motion.div layoutId="source-card-documentos" transition={morphTransition.layout} style={{ borderRadius: 8 }} // inline! no clase CSS > ... </motion.div> )
✓
borderRadius en style inline. Si usas una clase CSS (rounded-lg), Framer Motion no puede animar el borderRadius durante el morph porque no lo "ve" como propiedad animable. Con style={{ borderRadius: 8 }} si.

Breadcrumb acumulativo

El breadcrumb no reemplaza el titulo, lo acumula. "Crear curso" sigue visible pero se vuelve text-text-muted y clickable (lleva de vuelta a choose). Cada segmento nuevo entra con opacity + x fade via AnimatePresence.

Ir hacia atras: goBackToChoose

const goBackToChoose = useCallback(() => { startInstant(() => { // useInstantLayoutTransition setPhase('choose') setSource(null) }) }, [startInstant])
i
useInstantLayoutTransition es un hook oficial de Framer Motion. Todos los cambios de estado dentro de su callback se aplican sin animar los layoutId. Sin esto, al volver atras la card haria un morph inverso (grande → pequena), que se ve raro. Con el hook, la card simplemente aparece en su posicion original sin animacion.

Auto-propuesta al entrar

Cuando el phase cambia a 'schema' por primera vez (desde 'details' y sin nodos), se dispara automaticamente la propuesta de esquema.

// useEffect que detecta la transicion details -> schema const prevPhaseRef = useRef<Phase>('choose') useEffect(() => { if (phase === 'schema' && prevPhaseRef.current === 'details' && proposedNodes.length === 0) { void proposeSchema(density) // llama al endpoint } prevPhaseRef.current = phase }, [phase])

La funcion proposeSchema

const proposeSchema = useCallback(async (d: number) => { // 1. Abortar llamada anterior si existe proposeAbortRef.current?.abort() const abort = new AbortController() proposeAbortRef.current = abort setProposing(true) // muestra "Disenando el esquema..." setProposeError(null) try { // 2. Llamada directa con post() del api client const result = await post<{ nodes: ProposedNode[] }>( '/ai/schema-propose', { title, description: idea || undefined, intent_density: d } ) // 3. Solo actualizar si no fue abortado if (!abort.signal.aborted) { setProposedNodes(result.nodes) setProposing(false) } } catch (err) { ... } }, [title, idea])
!
AbortController. Si el admin cambia la densidad rapido (el slider tiene debounce de 400ms), la llamada anterior se aborta. Esto evita que llegue una respuesta vieja y sobreescriba la nueva.

Slider de densidad

Admin mueve el slider → handleDensityChange(newDensity)
Actualiza density inmediatamente (React state)
Debounce 400ms → proposeSchema(newDensity) si estamos en fase schema
Mientras carga: muestra "Disenando el esquema..." (la lista de nodos desaparece)
Respuesta → setProposedNodes(result.nodes) → la lista se repinta

Operaciones locales (sin backend)

Accion Handler Que hace
Editar titulo de nodo onNodeTitleChange(i, v) setProposedNodes con map, reemplaza el titulo del nodo i

Estas operaciones mutan React state directamente. Son instantaneas, sin llamada al servidor. No hay drag & drop ni edicion de summary/outcome todavia.

Componente SchemaContent

SchemaContent (linea 871) es un componente funcional que recibe todo por props. No tiene estado propio. Tiene tres estados de render:

Condicion Render
proposing === true Texto centrado: "Disenando el esquema..." + titulo del curso
proposeError !== null Mensaje de error en rojo
nodes.length === 0 "No se generaron nodos"
Default (hay nodos) Layout 2 columnas: sidebar (densidad + stats + boton) | lista de nodos

Estructura de un ProposedNode

interface ProposedNode { title: string // editable inline summary: string // visible, NO editable outcome: string | null // NO visible en la UI actual criticality: string // 'critical' | 'recommended' | 'context' default_ui_format: string // NO visible en la UI actual estimated_minutes: number // visible en badge + sum en sidebar source_headings: string[] // NO visible en la UI actual prerequisites: number[] // NO visible en la UI actual }
!
Campos ocultos. El endpoint devuelve outcome, default_ui_format, source_headings y prerequisites, pero la UI actual no los muestra ni permite editarlos. Estos son campos que podriamos exponer en la mejora de UX.
Fase 3 → Assign: "Crear curso"
→
handleCreateFromSchema()
persiste en BD

Este es el momento en que los datos pasan de React state a base de datos. Antes de este click, nada existe en el servidor.

POST /courses — Crea el curso (titulo, descripcion, source_document_id)
PUT /courses/{id}/schema — Escribe los nodos del esquema (transforma ProposedNode[] al formato de la API)
setPhase('assign') — Pasa a la pantalla de asignacion

Transformacion de datos

Los nodos propuestos por la IA se transforman antes de enviarse al servidor. Cada ProposedNode se convierte en un nodo de esquema con campos adicionales:

const schemaNodes = proposedNodes.map((n, i) => ({ title: n.title, summary: n.summary, outcome: n.outcome, criticality: n.criticality, position: i + 1, // orden secuencial mastery_threshold: // derivado de criticality n.criticality === 'critical' ? 0.9 : n.criticality === 'recommended' ? 0.8 : 0.7, estimated_minutes: n.estimated_minutes, default_ui_format: n.default_ui_format, skill_id: null, // no asignado aun seed_lesson_id: null, // no hay leccion semilla source_document_id: sourceId ?? null, // si vino de documento source_headings: n.source_headings, prerequisite_node_ids: [], // siempre vacio (!) archived: false, }))
!
prerequisite_node_ids siempre vacio. El endpoint /ai/schema-propose devuelve prerequisites: number[] (indices), pero handleCreateFromSchema los ignora y siempre envia []. Los prerequisitos del esquema propuesto por la IA se pierden.

Mapa de estado completo

Todo el estado del wizard vive en CreateCourse via useState. No hay context, no hay store, no hay URL params.
